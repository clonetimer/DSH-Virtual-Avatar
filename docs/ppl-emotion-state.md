# PPL-2：情绪状态与互动意图

## 1. 状态所有权

PPL Runtime 中的 `state.physical` 和 `state.emotion` 描述鲸鱼娘自身，不描述用户。

当前持久化状态：

| 字段 | 含义 | 主要变化来源 |
|---|---|---|
| `state.physical.fatigue` | 鲸鱼娘自身疲劳 | 明确的休息建议事件 |
| `state.emotion.anxiety` | 鲸鱼娘自身焦虑 | 安慰、互动恢复、负向互动 |
| `state.emotion.grief` | 鲸鱼娘自身悲伤 | 安慰和逐轮恢复 |
| `state.emotion.anger` | 鲸鱼娘自身愤怒 | 明确负向互动和逐轮恢复 |
| `state.emotion.embarrassment` | 鲸鱼娘自身羞赧 | 赞美、正向互动和逐轮恢复 |

这些状态均使用 PPL Core 0.3 的 Float01 语义类型。Runtime 通过 PPL Core 的 Float01 clamp 将提交结果限制在 [0,1]。

## 2. 互动事件分类

事件由 Host 侧确定性规则分类，PPL 和好感度结算复用同一个分类结果。

| 事件 | 语义 | 状态/行为结果 | 好感度 |
|---|---|---|---:|
| `USER_STRESS_DISCLOSURE` | 用户表达自身疲惫、焦虑、压力或难过 | 进入支持性回应模式 | 0 |
| `USER_SUPPORT_REQUEST` | 用户主动请求陪伴、安慰或拥抱 | 进入陪伴支持模式 | 0 |
| `COMFORT` | 用户安慰鲸鱼娘 | 增加信任与依恋，降低角色焦虑/悲伤 | 0 |
| `CHARACTER_REST_ENCOURAGEMENT` | 用户明确建议鲸鱼娘休息 | 降低角色疲劳和焦虑 | 0 |
| `PRAISE` | 用户明确赞美鲸鱼娘 | 增加角色羞赧，表达更容易害羞 | +1 |
| `POSITIVE_INTERACTION` | 明确的正向亲密互动 | 增加依恋和轻微羞赧 | +1 |
| `NEGATIVE_INTERACTION` | 明确针对角色的负向互动 | 增加角色愤怒/焦虑，降低依恋 | -1 |
| `CONFESSION` | 明确告白 | 由 PPL 关系转换规则决定 | +1 |

普通问候、寒暄和没有明确互动意图的消息归为 `MESSAGE`，不会自动增加好感度。

分类结果包含 `subject`、`signal`、`classification.method` 和 `classification.rule`，可在审计事件中追溯。

## 3. 用户情绪与角色状态隔离

- “我好累”“最近工作压力很大”属于用户自我表达，触发支持性回应，不会被解释为用户正在安慰鲸鱼娘。
- “你辛苦了”属于用户安慰角色，可以触发信任与依恋规则。
- “你休息一下吧”属于角色休息建议，只降低鲸鱼娘自身疲劳，不增加关系分数。
- “陪陪我”“抱抱我”属于用户支持请求，不会因为请求陪伴而增加好感或依恋。
- 用户短暂的疲劳、压力、焦虑或悲伤只参与当前回合的人格行为解析，不会自动写入长期记忆。

## 4. 提交与恢复

PPL `resolve()` 只生成效果和待提交状态变更。Host 仅在模型返回 `completed` 或 `max-tokens` 且回复非空时调用 `finalize()`，随后与对话记录、关系状态和好感成长一起进行事务提交。

模型超时、中断、空回复和其他失败终止原因不会提交本轮 PPL 状态变化。重复事件由角色事件账本和成长事件幂等机制保护。

旧存档加载时，Runtime 会将新增的情绪状态默认值与已有状态递归合并：已有值优先保留，缺失字段补入 PPL Persona IR 的默认值。

## 5. UI 与诊断

陪伴界面显示鲸鱼娘自身的疲劳、焦虑和羞赧指标；完整情绪状态同时出现在只读诊断数据中。界面明确标记为“角色状态 · PPL”，避免将其误解为对用户的心理或健康评估。
