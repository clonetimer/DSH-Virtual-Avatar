# DyberPet 本地动作库与持久化导入（dev.11）

## 用户入口

鲸鱼娘 → 更多 → 角色与外观 → 动作包预览。

## 导入流程

1. 选择包含 `pet_conf.json`、`act_conf.json` 和 `action/*.png` 的 DyberPet 角色目录。
2. 先运行本地预览，检查角色形象、动作名称、帧顺序和播放节奏。
3. 只有用户明确点击「导入到本地动作库（不启用）」才会开始持久化。
4. Host 创建 15 分钟有效的导入会话；浏览器逐张上传原始 PNG 二进制，不把所有图片合并成一个大型 JSON 请求。
5. Host 校验会话、帧路径、Content-Type、PNG 文件头、单帧大小和总大小；全部帧到齐后才提交。
6. SQLite 保存角色配置、动作目录、帧索引、SHA-256、大小、来源哈希和时间；PNG 使用独立 pack UUID 目录原子写入。
7. 本地动作库显示包名称、帧数、容量、导入时间和来源哈希前缀；可再次预览或卸载。

## 数据完整性和安全

- 每包最多 1200 帧；单帧不超过 6 MiB；总计不超过 64 MiB；每份 JSON 配置不超过 64 KiB。
- 只允许 `action/<prefix>_<number>.png`，拒绝路径穿越、重复帧和未声明帧。
- Host 对 PNG 文件头再次校验；写入使用临时目录、独立 pack UUID、原子目录重命名和 SQLite 事务。
- 每帧保存 SHA-256 和字节数；预览读取时重新核对哈希，检测磁盘篡改或损坏。
- 导入会话 15 分钟过期；退出插件时清理未完成的 staging 目录；关闭导入面板会中止上传并请求清理会话。
- 重复导入相同内容会按 source hash 识别，不重复占用磁盘。
- 卸载必须由用户确认；目录先重命名为删除暂存目录，数据库事务成功后再清理文件。数据库失败则尝试恢复目录。
- 插件备份包含 `assets/motion-packs`，可随数据库和其他媒体一起备份。

## 角色应用边界

导入动作包只代表将其保存到本机动作库，不代表已启用到鲸鱼娘。当前用户提供的 DyberPet 示例可能是 Kitty/ChrisKitty，与鲸鱼娘外观不一致，因此默认保持未启用状态。不得把无关角色素材自动替换到鲸鱼娘立绘。

正式启用需要具备与鲸鱼娘形象一致且授权明确的多帧素材包，并单独完成人工形象确认、动作绑定、PPL 状态映射、真实桌面播放、故障回滚与长时间运行测试。

## 备份、恢复和卸载

- SQLite 记录和 PNG 文件都位于插件私有存储目录。
- `createBackup` 会复制整个 assets 目录，因此已导入动作包自动进入备份清单和哈希校验。
- `deleteMotionPack` 要求 `confirmed: true`，并记录 `MOTION_PACK_REMOVED` 审计事件。
- 卸载动作包不会删除聊天记录、记忆、关系或原始 Whale 立绘。

## 验证

- SQLite 测试覆盖导入、重复导入、关闭并重新打开数据库后的持久化、帧哈希校验、备份包含动作资源、显式卸载和路径/PNG 拒绝。
- Host 集成测试覆盖开始会话、逐帧二进制上传、未完成提交拒绝、提交、动作帧 GET、角色状态不变、非法 PNG 和不安全路径。
- Client 测试覆盖明确导入按钮、本地动作库列表、已导入预览、卸载、退出中止上传和临时 Blob URL 释放。
- Node 24 / 24.9.0 GitHub Actions 验证完整套件、PPL 编译、DSH Classic Client 加载和 npm 包检查。
