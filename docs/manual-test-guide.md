# DSH Virtual Avatar 功能使用与桌面验收指南

适用版本：DSH Desktop 0.2.2-rc.1、DSH Virtual Avatar dev.19。

## 1. 模型设置与聊天

1. 在鲸鱼娘窗口点击「更多 → 模型设置」。
2. 在「模型服务商」中选择 DSH 当前已启用的 Provider。
3. 从模型目录选择模型；如果该 Provider 没有提供模型目录，可手动填写模型 ID。
4. 点击「测试连接」。连接测试针对当前页面中的未保存模型草稿，不会修改已保存路由或 DSH 全局默认模型。
5. 测试成功后，「保存鲸鱼娘模型」按钮才会启用；点击保存并应用。
6. 返回聊天窗口，发送一条新消息，并在运行诊断中核对实际 Provider / Model。
6. 打开「运行诊断」，确认显示的 Provider / Model 与模型设置一致。

模型设置只影响鲸鱼娘，不会修改 DSH 其他 Agent 的全局默认模型。「恢复 DSH 默认」会清除鲸鱼娘独立选择，重新跟随 DSH 默认模型。若 Provider 未在 DSH 启用，先到 DSH 主界面配置 Provider。

## 2. 聊天与桌面交互

- 发送普通文本，确认用户消息与鲸鱼娘回复都进入聊天记录。
- 点击左侧鲸鱼娘立绘，确认摸摸反馈、表情和气泡出现。
- 收起窗口，再从桌宠入口打开，确认聊天记录和角色状态仍在。
- 发送失败时确认输入草稿保留；错误提示应说明本次对话未完成，不应将失败误报为成功。

## 3. 互动场景与 PPL 状态

- 分别选择「私密空间」和「公开场合」。
- 在两种场景中发送相同的日常表达，观察回复语气与角色状态差异。
- 发送赞美、安慰、压力表达或休息相关内容，观察心情、害羞等状态是否合理变化。
- 不以单条消息推断关系阶段；通过多轮互动和关系记录观察阶段变化。

## 4. 历史与关系记录

- 使用「搜索对话」搜索一段已经发送过的关键词。
- 加载更早历史，确认分页结果与时间顺序。
- 打开「关系记录」，检查完成对话、好感变化和阶段变化事件。

## 5. 长期记忆与摘要

- 发送包含稳定偏好的消息，检查是否出现记忆候选。
- 只有在用户确认后才保存记忆。
- 在「查看记忆」中搜索、置顶、编辑、取消置顶、删除并导出。
- 使用「整理长期摘要」生成候选；检查来源与内容后再确认更新。不要把候选生成等同于自动写入。

## 6. 背景与角色设定

- 在「背景与亮度」中切换「深海工坊夜景」和「海边书房」。
- 调整遮罩强度，默认建议从 22%～32% 开始；数值越低，背景越清晰。
- 点击「应用背景设置」，关闭面板并确认聊天气泡和文字仍有足够对比度。
- 在「角色设定」中修改称呼或语气，保存后发送新消息确认效果。

## 7. 动作库与动画

动作功能分为三层：

1. **预览**：选择包含 pet_conf.json、act_conf.json 和 action/ PNG 帧的 DyberPet 文件夹。预览只在当前页面临时播放，不会保存，也不会让鲸鱼娘自动动。
2. **导入**：确认动作帧正常后，点击「导入到本地动作库」。导入后刷新列表，再次打开已保存动作包。
3. **绑定**：只有素材角色外观与鲸鱼娘一致且拥有使用权时，才勾选确认并绑定。之后检查待机、思考、回复、摸摸、休息和 PPL 情绪映射。最后解除绑定。

Kitty、ChrisKitty 等其他角色的素材只能用于验证 DyberPet 格式和播放器，不能当作鲸鱼娘素材。若暂时没有匹配的鲸鱼娘多帧素材，可以完成预览和本地导入测试，但不要绑定。

## 8. 备份、恢复与诊断

- 升级前点击「备份与恢复 → 立即创建备份」。
- 检查备份列表和有效性。恢复会覆盖当前角色状态，测试恢复前务必确认已有可用备份。
- 打开「运行诊断」，确认模型、PPL Runtime、Persona IR、SQLite、记忆数量、动作包数量和最近错误。
- 导出诊断 JSON，检查报告中不包含 API Key 或其他凭证。

## 9. 建议验收顺序

模型设置与连接测试 → 聊天 → 收起/重新打开 → 互动场景与 PPL → 历史与关系 → 记忆与摘要 → 背景与角色设定 → 动作预览/导入/绑定 → 备份恢复 → 诊断导出。


## 10. 聊天失败恢复与功能向导（dev.16）

- 发送一条消息后，在测试环境模拟断网或中断；确认输入内容保留，并出现具体错误原因。
- 点击“重试本次消息”。若第一次请求已经在 Host 完成提交，重试应取回原回复，不应再增加一组重复聊天记录，也不应重复增加好感/关系成长。
- 对模型未配置的场景，错误提示应提供“打开模型设置”；完成模型设置后再发送。
- 打开“功能测试指南”，分别使用快捷入口进入模型设置、对话搜索、记忆管理、关系记录、背景设置、动作库、备份与诊断；每次都能通过“返回聊天”回到主界面。
- 更换 Provider 或 Model 后，旧的连接测试结果应清空；保存新模型后需要重新测试。


## 11. PPL 规则执行审计（dev.16）

1. 发送一条普通消息，打开「更多 → 运行诊断 → 查看 PPL 执行记录」。
2. 确认记录显示事件类型、交互场景、Persona IR 版本和哈希。
3. 展开「查看规则、状态和约束详情」，检查命中规则、效果轨迹数量、状态变化前后值和人格不变量结果。
4. 发送「你辛苦了」或赞美，确认相应 PPL 规则被命中，且信任、羞赧等状态变化与事件类型一致。
5. 在测试环境触发 PPL 不变量失败，确认记录显示错误代码和诊断信息，角色状态没有提交。
6. 检查普通诊断导出与 PPL 审计记录均不包含原始 API 凭证；PPL 失败审计不重复保存用户原始消息正文。


## 12. PPL 可视化人格调校（dev.17）

1. 打开「更多 → 角色与外观 → PPL 人格调校」。
2. 检查「性格特征」和「表达方式」两组参数，确认每个滑块均有中文说明、百分比数值和有效范围。
3. 分别应用「温柔陪伴」「活泼元气」「稳重克制」预设，确认滑块即时更新；点击「恢复默认」后，参数应回到 Persona IR 的基础值。
4. 修改温柔度、活泼度、表达详略和情绪表达，点击「预览规则效果」。
5. 确认私密日常、安慰支持、赞美鼓励、公开场合四种场景均通过 PPL 校验，并显示各自命中的规则。
6. 点击「保存并应用」，确认提示说明从下一轮对话开始生效。
7. 发送普通消息、安慰消息和赞美消息，检查回复风格及 PPL 审计记录中的 IR 哈希。
8. 重新启动 DSH Desktop，确认已保存的参数仍然生效。
9. 点击「恢复默认」并保存，确认参数恢复基础值；关系阶段、历史对话、记忆和动作包均保留。
10. 在两处同时打开角色窗口并模拟并发修改，确认旧 revision 保存时会得到冲突提示，而不会覆盖较新的配置。


## 13. P5-C2 多角色运行时验收（dev.18）

1. 备份现有鲸鱼娘数据后安装 dev.18。打开窗口，确认可以在「切换角色」中选择鲸鱼娘与「庄方宜 · PPL 参考角色」。
2. 先在鲸鱼娘中发送独特消息，确认其历史和好感度正常；切换到参考角色时，界面应改为中性标识，不能显示鲸鱼娘立绘。
3. 在参考角色中发送一条普通消息和一条安慰消息。确认聊天记录只在当前角色出现，PPL 关系状态按参考角色规则变化。
4. 在参考角色的「私人记忆」中新增、编辑、置顶和删除一条内容。返回鲸鱼娘，确认这些内容不会出现在鲸鱼娘的记忆列表中。
5. 在参考角色的「模型设置」中选择 DSH 已启用的模型并测试连接。返回鲸鱼娘，确认鲸鱼娘的模型选择没有被更改。
6. 在参考角色的「人格调校」中调整表达详略、情绪克制等字段，执行四场景规则预览并保存。确认重新打开后参数保持，并能在该角色审计记录中查看变更。
7. 切换回鲸鱼娘，确认之前的消息、关系、记忆、外观、动作包和 PPL 参数保持不变。
8. 退出并完全重启 DSH Desktop，确认上次选择的角色能够恢复；重复角色切换，检查聊天记录、记忆和设置均不串线。
9. 测试两个窗口同时发送消息、切换角色的情况；不得把前一个角色的消息、LLM 回复或状态写入另一个角色。
10. 验证角色无效 ID、跨角色重复事件 ID 和错误记忆 ID 会被拒绝，原有数据不应发生变化。

注：参考角色的 PPL 源文件和已发布 IR 均来自固定的上游版本，二者并非完全一致；本次仅使用上游正式参考 IR 作为运行依据，不宣称两者编译产物完全一致。参考角色暂不附带专属立绘与动画。


## 14. 角色形象与模型设置修复（dev.19）

### 庄方宜角色形象
1. 切换到「庄方宜 · PPL 参考角色」。
2. 确认左侧显示独立 Q 版立绘，收起后角色入口显示同一形象，聊天回复旁显示小头像。
3. 确认没有显示鲸鱼娘立绘或鲸鱼娘动画；当前庄方宜使用原创 AI 生成概念图，尚未包含专属表情/动作帧。
4. 若立绘未加载，打开 DSH 插件诊断，检查 `/api/dsh-virtual-avatar/assets/characters/zhuang-fangyi/portrait.svg` 是否返回 `image/svg+xml`。

### 模型设置与连接
1. 打开庄方宜的「模型设置」，应先显示当前生效 provider/model、服务商目录加载状态和模型选择区域，不应出现空白页。
2. 如果没有服务商，先到 DSH 的模型设置启用服务商，再点击「重新读取目录」。
3. 选择服务商与模型；若目录没有列出模型，可手动输入模型 ID。
4. 点击「测试当前选择」。测试针对当前未保存的 provider/model 草稿，不得偷偷测试之前保存的路由，也不得提前保存模型选择。
5. 连接测试成功后，「保存并应用」按钮才会启用。保存后新对话才使用该角色专属模型。切回鲸鱼娘，确认鲸鱼娘和 DSH 主 Agent 的模型设置不变。
6. 发送两轮连续对话，检查历史 assistant 消息正常进入上下文，模型回复成功。
7. 若测试失败，确认界面显示错误代码、provider/model 和对应处理建议。特别区分 `TRANSPORT`、凭证错误、未启用服务商和额度限制。
8. 对瞬时传输故障，最多自动重试一次；连续失败时应保留输入，不写入 PPL 关系或角色状态。
9. 完全重启 DSH Desktop，确认角色专属模型选择与立绘仍然保留。
