# 产品需求规格（SRS）v0.2

状态：首发陪伴插件实施基线。未实现或未实机验收的能力不得标记为完成。

## 1. 产品定位

DSH Virtual Avatar 是一个面向 DeepSeek Harness Web/Desktop 的单插件陪伴角色系统。首发仅启用 DeepSeek 鲸鱼娘，提供自由对话、长期记忆、关系成长和日常陪伴。

- **Companion Character**：独立的陪伴角色请求，拥有独立人格、状态和记忆。
- **Agent Persona**：不属于首发交付范围；陪伴角色不得覆盖主 Agent 的人格、工具权限或任务执行身份。
- 上游 Whale Galgame 仓库仅作为角色设定、存档和素材来源；当前产品不承接其剧情游戏功能。

## 2. 用户与使用场景

- 用户在 DSH 中打开鲸鱼娘，进行自由输入的日常对话。
- 用户希望角色跨会话记住经过确认的重要事实、偏好、共同经历和未完成约定。
- 用户希望关系随着持续互动自然变化，但成长规则可解释、可审计且不能通过重复请求刷取。
- 用户可以查看、置顶、删除记忆，预览长期摘要并决定是否确认。
- 用户希望角色立绘、表情、背景、昵称和称呼可配置。
- 用户已有 Whale 存档，希望安全迁移 DeepSeek 角色数据，同时保留原始存档和其他角色数据。

## 3. 功能需求

### FR-01 单插件安装
一个 DSH 插件包完成 Host、Client、API 和角色存储接入。用户不需要分别安装 virtual-person 和 whale-galgame，也不需要常驻启动 PPL Gateway。

### FR-02 单角色首发与扩展边界
- 首发只启用稳定 ID 为 `deepseek` 的鲸鱼娘。
- 保留未来多角色 Registry 的扩展边界，但其他五个上游角色不在本阶段迁移或启用。
- 角色状态、记忆、事件和配置均按角色 ID 隔离。

### FR-03 陪伴请求与主 Agent 隔离
- Companion Character 提示词只进入本插件的陪伴对话请求，不进入主 Agent 普通工作请求。
- 角色不能执行工具调用、修改文件或代替主 Agent 完成任务。
- 人格关系阶段只影响亲密表达，不改变事实判断、工具权限或安全边界。
- 每次请求记录人格版本、PPL IR hash、状态 revision 和上下文预算诊断。

### FR-04 长期记忆与连续性
- 角色私有记忆与共享用户事实分开存储，首发默认仅角色私有。
- 支持相关检索、相似合并、置顶、取消置顶、删除和上下文预算控制。
- 自动提取只产生候选，不自动写入；重要事实必须经用户确认或用户主动添加。
- 长期相处摘要基于已有对话、已确认事实、共同经历和记忆条目生成候选。
- 摘要候选包含 sourceHash 和 expectedRevision；用户确认时执行 revision 乐观锁，避免覆盖并发更新。
- 记忆来源、时间、更新时间、所属角色和写入事件可追溯。

### FR-05 关系与成长
- 好感度/等级沿用 Whale 既有进度曲线和等级结转语义。
- 正向好感成长每日最多计入两次；负向互动仍按规则处理，不得绕过成长服务直接修改数值。
- 信任度、依恋度、关系阶段和角色内部情绪/精力由 PPL 规则与运行时状态管理。
- 状态更新必须来自具有稳定 event ID 的已完成互动；重复事件幂等，ID 复用但 payload 不同必须报冲突。
- 模型中断、空输出、失败或取消的回合不得提交关系和成长状态。
- UI 不得直接提交 trust、attachment 或 relationship stage 数值。

### FR-06 陪伴界面
- 提供轻量悬浮入口和独立陪伴面板，支持自由输入、流式回复、历史分页和忙碌/失败状态提示。
- 支持角色立绘、情绪表情、白名单内置背景切换。
- 支持记忆管理、整理记忆、摘要预览与用户确认、角色设定编辑。
- 当前不开发 Galgame 章节、剧情分支、剧情结局、游戏式回复选项、小剧场和 CG。
- 桌面宠物动画作为后续独立评估项，不阻塞首发陪伴链路。

### FR-07 数据迁移
- 支持 Whale 的 `DSH_HOME/storages/dsh-whale-galgame/global.json` 只读检查与迁移预览。
- 首发只导入 DeepSeek 角色；其他角色明确延期。
- 迁移前备份并 staging，预览后由用户确认提交；支持重复运行、报告和回滚。
- 未知字段与完整源 JSON 保留；迁移不得修改源文件。
- 迁移不得覆盖迁移后产生的新对话、关系或记忆状态。

### FR-08 诊断与可观测性
设置/诊断界面应展示插件版本、存储位置、当前模型、PPL Runtime 状态、记忆数量、迁移状态、上次错误和备份状态。诊断导出不得包含 API key，默认不得导出完整对话正文。

## 4. 非功能需求

- NFR-01 Node.js 最低版本为 22.19.0。
- NFR-02 默认仅使用 DSH_HOME 本地存储；本地服务接口不得无必要地暴露到非本机网络。
- NFR-03 所有持久化写入原子化或事务化；损坏输入不得破坏现有存档。
- NFR-04 角色记忆隔离；查看、确认、导出和删除行为透明。
- NFR-05 旧插件可并行保留作回滚，但迁移期间禁止两个插件同时写同一存档。
- NFR-06 许可清单逐文件保留，尤其 Whale CC BY-NC-SA 4.0 美术。
- NFR-07 单元测试、契约测试、迁移测试、DSH Host 测试、Web/Desktop 实机验收分别报告，不相互替代。

## 5. 默认产品行为

- 首次安装只启用 DeepSeek 鲸鱼娘，不覆盖主 Agent。
- 角色记忆默认私有；只有用户明确授权才允许跨角色共享。
- 自动记忆和摘要只提出候选；确认前不覆盖长期记忆。
- 迁移只预览不自动提交；必须由用户确认。
- 卸载不删除用户数据。
- PPL Runtime 不可用时明确显示降级状态；不得静默写入一份伪装为 PPL 成功的状态快照。

## 6. 验收场景

1. 插件启用后，主 Agent 普通请求不包含鲸鱼娘陪伴 Prompt。
2. 鲸鱼娘可以自由聊天；历史记录跨请求持久化并支持分页。
3. 角色记忆只被本角色检索；置顶条目在预算内优先保留。
4. 自动记忆候选和摘要候选在用户确认前不会改变持久化记忆。
5. 摘要确认使用 expectedRevision；并发更新冲突时拒绝覆盖。
6. 同一关系事件重复提交不重复增加好感；同 ID 不同 payload 报冲突。
7. 每日第三次及之后的正向成长不增加好感；跨日后重新获得成长额度。
8. 中断/失败回合不写入对话历史、关系和成长状态。
9. 迁移后原始 global.json hash 不变；仅 DeepSeek 角色数据进入新存储，其他角色和未知字段仍可从原始备份恢复。
10. Web/Desktop 分别完成真实安装、重启、对话、记忆确认和存档重载验收。
