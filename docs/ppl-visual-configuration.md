# PPL 可视化人格配置设计与验收

## 1. 目标

让非程序用户能够调整角色的基础性格与表达方式，并通过真实 PPL Runtime 预览修改效果。编辑器不是 PPL 源代码编辑器，也不直接修改规则、关系阶段或安全约束。

## 2. 配置边界

### 可编辑参数

| 分组 | 参数 | 范围 | 作用 |
|---|---|---:|---|
| 性格特征 | 温柔度 | 0.60–1.00 | 关怀、耐心和情绪支持倾向 |
| 性格特征 | 活泼度 | 0–1 | 俏皮、轻松和调侃程度 |
| 性格特征 | 主动表达 | 0–1 | 主动表达意见和建议的程度 |
| 性格特征 | 情绪克制 | 0–1 | 情绪表达的谨慎程度 |
| 性格特征 | 坦诚程度 | 0–1 | 表达自身感受的开放程度 |
| 表达方式 | 正式程度 | 0–1 | 礼貌、正式和克制程度 |
| 表达方式 | 表达详略 | 0–1 | 回复详尽程度 |
| 表达方式 | 情绪表达 | 0–1 | 情绪表达的直接程度 |
| 表达方式 | 动作描写 | 0–1 | 动作和表情描写程度 |

温柔度最低值与 PPL `CORE_TONE` 不变量一致。所有数值以 0.01 为步进。

### 不开放直接编辑

- PPL 规则的触发条件、优先级和效果语句；
- 关系阶段与阶段转换条件；
- PPL invariants、guides、semantic bindings；
- 角色身份、权限边界和安全约束；
- 上游 PPL 源文件及编译器生成的 Persona IR。

这些内容继续由经过版本控制的 PPL 源文件管理，避免 UI 编辑绕过编译和一致性检查。

## 3. 运行时架构

```text
Pinned Persona IR
       |
       v
Validated Configuration Overlay
       |
       v
Derived Persona IR ----> SHA-256 binding
       |
       v
PPL Runtime
       |
       +----> Private chat preview
       +----> Comfort/support preview
       +----> Praise preview
       +----> Public-space preview
       |
       v
Save with expectedRevision
       |
       +----> character_states.pplConfigOverrides
       +----> SQLite PPL_CONFIGURATION_UPDATED audit event
```

基础 IR 在内存中保持不可变。用户配置只覆盖白名单基础值；规则、状态提交、关系转换和安全不变量仍由同一 PPL 运行时执行。

## 4. 用户交互

1. 打开「更多 → 角色与外观 → PPL 人格调校」。
2. 通过滑块调整性格和表达参数。
3. 可选择三种预设：温柔陪伴、活泼元气、稳重克制。
4. 点击「预览规则效果」，真实运行四种典型场景并检查 PPL 解析及人格不变量。
5. 确认后点击「保存并应用」；新参数从下一轮对话开始生效。
6. 「恢复默认」先恢复编辑草稿，用户仍需点击保存，才会正式应用。

## 5. 持久化与恢复

- 配置 schema：`dsh-virtual-avatar.ppl-config/1`。
- 持久化字段：角色状态中的 `pplConfigOverrides`。
- 角色备份包含该配置。
- 保存使用角色状态 revision，过期写入返回 `REVISION_CONFLICT`。
- 配置变化和 IR 哈希写入审计历史。
- 恢复默认只清空配置覆盖，不清除关系、对话、长期记忆或动作包。

## 6. 验收标准

- 所有滑块均显示中文含义、当前百分比和允许范围。
- 预览调用真实 PPL Runtime，不调用 LLM，也不修改角色状态。
- 四种场景均通过不变量检查，并显示规则命中结果。
- 保存后 IR 哈希发生相应变化，下一轮对话使用新 IR。
- DSH 重启后参数保持。
- 恢复默认不影响关系、记忆、聊天记录和动作库。
- 过期 revision 不覆盖新配置。
